# 需求发现指南

只在用户尚未形成清晰工作台定义时读取。目标是用尽量少的问题找出真实工作流，而不是让用户填写一份冗长问卷。

## 先找真实事件

优先让用户描述最近一次真实任务：

- 什么事情触发了这项工作？
- 从哪里收到信息，用什么工具记录？
- 中间有哪些状态、截止日期和交接？
- 最终交付什么，怎样才算完成？
- 哪一步最常漏、最常重复或最难复盘？

真实事件通常比“你想要哪些模块”更能暴露需要的数据和交互。

## 信息维度

从以下维度选择当前最有信息增益的问题，每轮最多 3 个：

### 用户与频率

- 谁使用，是个人、固定小团队还是多个角色？
- 每天、每周、每月分别做什么？
- 同时管理多少对象，例如学生、客户、商单、项目或内容？

### 流程与异常

- 一个对象从进入到结束有哪些状态？
- 哪些节点有截止时间、提醒、审核、退回或归档？
- 哪些例外最常发生？

### 数据与来源

- 当前数据在聊天、Excel、文档、网盘还是其他系统？
- 必须保存哪些字段、附件和历史记录？
- 是否需要批量导入、导出、备份或从旧工具迁移？

### 联动与自动化

- 哪次录入应该自动更新其他页面？
- 哪些统计、提醒、计算或模板最能减少重复劳动？
- 哪些动作必须人工确认，不能自动执行？

### 交付与环境

- 只在当前电脑使用，还是要给别人安装、在线访问或多人协作？
- 是否允许联网，数据是否敏感？
- 用户更重视零安装、离线、本地文件可备份、跨设备还是权限管理？

### 视觉与可用性

- 需要什么气质或参考界面？
- 主要设备、屏幕尺寸和使用时长是什么？
- 是否有打印、无障碍、暗色模式或高密度表格要求？

## 推荐式提问

不要只抛开放题。根据已知信息给一个可改的推荐，例如：

> 你现在是个人使用，而且数据主要来自 Excel。我建议第一版做“本地单机 + Excel 导入导出 + JSON 完整备份”，暂不做账号和云同步。你是否需要在多台电脑之间共享？

## 范围收敛

当用户一次提出很多模块时，按三个层级整理：

- `核心闭环`：没有它就解决不了主要问题。
- `第一版增强`：能明显减少重复劳动，但不阻断闭环。
- `以后再做`：依赖外部系统、实现成本高或使用频率低。

用“使用频率 × 出错代价 × 节省时间”判断优先级。不要仅因为功能听起来先进就放入第一版。
